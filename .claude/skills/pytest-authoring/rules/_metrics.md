# rule card 채택 근거 (실측 기록)

카드는 직관으로 늘리지 않는다. 고정 벤치마크 세트에 대한 A/B 결과만 근거로 삼는다.

## 벤치마크 세트

`benchmarks/targets.json` — 순수 함수 20개 + I/O 의존 10개 (대상 repo에서 1회 선정 후 고정).
카드를 바꿀 때마다 이 세트로만 비교한다. 세트를 바꾸면 과거 수치와 비교 불가.

## 측정 방법

```
동일 타깃 · 동일 temperature · candidates=1 · repair=0 으로
card 有 / card 無 각각 3회 실행 → 1회 시도 통과율 비교
```

## 기록표

| card | 겨냥한 실패 유형 | 통과율 (無 → 有) | 판정 | 측정일 |
|---|---|---|---|---|
| pure-function | — (기준선) | — | 보류 | |
| patching | `AttributeError` / 패치 위치 오류 | → | 보류 | |
| time-and-random | flaky, 시각 의존 | → | 보류 | |
| exception-paths | `Failed: DID NOT RAISE` | → | 보류 | |
| filesystem | `FileNotFoundError`, 인코딩 | → | 보류 | |
| class-and-state | 테스트 간 간섭 | → | 보류 | |
| characterize | `AssertionError` (기대값 오답) | → | 보류 | |

`판정`: 채택 / 폐기 / 보류(미측정)

## 함께 측정할 항목

- **카드 언어**: 한국어 vs 영어 프롬프트. 소형 모델은 영어 지시 준수율이 더 높은 경우가 많다.
  카드 본문만 영어로 바꾼 변형으로 1회 비교해 볼 것
- **카드 장수**: 1장 vs 2장 vs 3장. 3장에서 오히려 떨어지는 지점을 찾는다
- **few-shot 유무**: 같은 repo의 기존 테스트 1개를 넣었을 때의 차이

## 원칙

카드가 많아질수록 좋아지는 게 아니다. 카드 하나는 다른 카드의 자리를 뺏고,
프롬프트가 길어지면 지시 준수율 자체가 떨어진다. **통과율을 유의하게 올리지 못한 카드는 지운다.**
